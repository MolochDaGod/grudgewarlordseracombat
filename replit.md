# Grudge Gladiators (formerly Saber Academy)

A playable third-person 3D browser game by Grudge Studio (dark gold/ember branding; logo + banner in `artifacts/saber-academy/public/brand/`; the code directory keeps the `saber-academy` slug): a lone guardian survives five waves of foes in a temple arena. You pick a real champion from the Grudge roster (live from Cloudflare D1) and fight as their real 3D model (GLB from Cloudflare R2), wielding their real embedded weapon and two class-specific signature skills. Three modes: Survival (five waves), Testing Grounds (free-play sandbox), and Animation Test (a diagnostics lab to inspect the character's skeletal animation and directional movement). Built with three.js and the `grudge-studio` npm 3D SDK.

### Enemies
- Lesser minions: two low-poly FBX packs (marauders + elves) in `artifacts/saber-academy/public/models/minions/` pad every survival wave at half HP and 0.88 scale; the Fire Elf is a ranged staff caster from wave 2. They ride the Mixamo library retargeted onto their Blender-style rig (`STANDOUT_BONE_MAP` in retarget.ts).

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Physics/collision (saber-academy): `@dimforge/rapier3d-compat` (kinematic char controllers) + `three-mesh-bvh` (mesh-accurate ground + weapon-vs-body melee)

## Where things live

- `artifacts/saber-academy/src/game/SaberGame.ts` — the game engine (vanilla three.js + grudge-studio): scene, player, enemies, combat, waves, movement, game loop. Async `start(player, enemyPool, mode)` loads models, guarded by a `startVersion` token, and calls `ensurePhysics(token)` to bring up Rapier + BVH before play begins. Also owns the signature-skill system (cast/cooldown/force gating + a sprite VFX system: projectiles, novas, impact flashes), the `mode` (`"waves"` vs `"sandbox"` vs `"animtest"`) and the sandbox public methods (`sandboxSpawn`/`sandboxClear`/`sandboxRefill`). The **Animation Test** lab (`mode === "animtest"`) loads the champion through the normal skeletal pipeline but spawns nothing and never dies; it locks the body facing to the camera heading (strafe-locked, instead of the usual turn-to-face) so A/D produce real lateral velocity and the `strafeLeft`/`strafeRight` clips actually fire — the main combat modes are turn-to-face, which makes strafe ~0 so those clips never play. `forcedClip` (set via `animTestPlay`/`animTestFree`/`animTestToggleAuto`) overrides movement-derived animation with a synthetic `AnimState` (`animStateForClip`) so each clip can be inspected in isolation; `updateAnimTest` auto-cycles clips. `loadPlayerInstance` records a diagnostic `playerAnimMode` string per branch, and `snapshot()` emits `HudState.diag` (`AnimDiag`: animMode, `skeletal` = `!!playerInst.mixer`, currentClip, keys held, speed/strafe/facing) only in animtest. The no-death gate in `damagePlayer` is `mode !== "waves"`. `classFor(hero)` resolves a champion's skill class (classId → faction → weapon category). Dead enemies are marked `alive=false` + disposed in `killEnemy`, then compacted out of the array each render frame (so endless sandbox play does not grow it unbounded). Offense: light attacks (LMB) chain a 3-step combo (`comboStep`, alternating arc + escalating damage) when re-pressed inside `COMBO_CHAIN_WINDOW`; a press during a swing's `COMBO_CANCEL` tail is buffered (`bufferedAttack`/`bufferedHeavy`) and fired when the swing ends. Heavy attacks (Shift+LMB) use `HEAVY_DUR` with longer reach/damage/knockback; an LMB while airborne is an air/plunge strike (`attackAir`, dives `velocityY` down). Each swing's active window keys off a per-attack `attackDur`. **Tab-target / lock-on**: `targetEnemy` is the focused enemy and `targetMarker` is a lazily-built billboarded chevron sprite hovering over it. `Tab` (`cycleTarget`) cycles alive enemies nearest-first; plain **RMB** (`focusTarget`) toggles lock-on, picking the enemy nearest the camera aim (`bestTargetInView`, forward-cone) or the nearest overall. While locked, `updatePlayer` faces the body at the target every frame (strafe-locked like animtest) and `startSwing` auto-aims `facing` at the locked/nearest enemy (`nearestEnemyForAttack`) so simple LMB attacks connect. `updateTargetMarker` (called after the dead-enemy compaction) tracks the target and drops the lock when it dies; `setTarget` emits so `HudState.targetLocked` lights the crosshair. The strafe-roll "right" basis in `updatePlayerAnim` is `(-cos(facing), 0, sin(facing))` to match the camera/movement right (`camRight`) so `strafeLeft`/`strafeRight` clips match the actual sidestep. Combat defense: dodge-roll i-frames (`iFrames`, double-tap force-dash, also allows one mid-air **air dash** via `airDashUsed`, reset on landing) and a **block** (Shift+RMB held → `blocking`, gated on held Shift + force). The **timing parry** is a **perfect-guard**: engaging a block (the `blocking` false→true edge in `updatePlayer`, detected via `prevBlocking`) opens `PARRY_WINDOW`, so a hit landing right as you raise guard is parried, while a held guard resolves as a normal block. One parry per press (holding does not re-arm). This reuses the block input (Shift+RMB) — no conflict with the tap-RMB lock-on. `damagePlayer(amount, attacker?)` resolves in order: i-frames skip damage → a hit inside the parry window becomes a parry (`parrySuccess`: clash + flash VFX via `spawnClash`, force reward, attacker stunned `STUN_TIME` + knockback) → a block takes **zero** damage but drains force and shoves the player back (`pushPlayer` impulse routed through the dash-bleed path so smoothing doesn't wash it out) → otherwise full damage + combo reset. A parried enemy's `stunTimer` freezes its chase + attack until it expires or `damageEnemy` clears it on the next hit. Melee uses a per-swing `swingId` so each strike registers at most one hit per enemy. **Gesture combat**: the HUD crosshair rides the weapon point during swings (`updateAimCrosshair` projects the blade tip / hand each frame through the per-frame `onAim` callback — DOM-updated, not HudState). Holding **LMB** past `DRAW_HOLD_T` enters a draw mode (mouse deltas trace a limited-ink screen stroke, camera frozen, trail painted via `onDraw`); release projects the stroke onto a world curtain at sword reach and sweeps it over `SLASH_EXEC_T` (`executeDrawnSlash`/`updateDrawnSlash`, once-per-enemy damage, force cost). Starting a draw cancels the in-flight swing + buffered combo so it's an alternative input, not a layer. **MMB drag** draws a defensive ribbon (`placeGuard`): a translucent vertical wall lasting `GUARD_LIFE` that intercepts enemy bullets (checked in the bullet loop) and melee hits (`guardIntercepts` in `damagePlayer`, sampled at ≤0.25u along ribbon spans so fast strokes leave no gaps). Pointer-lock loss / run reset clears all transient input via `resetPointerState`; game over calls `clearVfx` so ribbons don't linger. **Movement Motivation (MM)** drives enemy positioning: each enemy gets a signed `mm` scalar (+100 close-gap/melee .. -100 keep-distance/ranged) from its weapon at spawn (`mmForWeapon`, see `mm.ts`), mapped to a `desiredRange` standoff (`enemyStandoff`). `updateEnemies` holds that range for every enemy — approach when farther than `desiredRange`; but only enemies with a ranged attack (`e.ranged`) back off (inside `desiredRange - KITE_BAND`) or strafe within the band, so melee-only enemies (including flavor-ranged roster champions that lack a projectile) always commit to attack range instead of running away. This replaced the old fixed `GUNNER_NEAR/GUNNER_FAR` kite thresholds and the `dist>2.4` melee chase. Ranged **Heavy gunners** (`Enemy.ranged`, built via `loadGunnerDef()`/`instantiateHeavy`) carry a strong negative MM so they kite to hold range, strafe (`strafeDir`), and `fireBullet(e)` on a cooldown instead of swinging; bullets are `EnemyShot`s in `enemyShots[]` that travel in `updateVfx` and, on reaching the player's chest, resolve through `damagePlayer(dmg, shooter)` — so the existing parry/block/i-frame ladder intercepts them for free (block = zero damage + force drain + pushback, parry = negate + stun the shooter). `clearVfx` clears `enemyShots`.

The wind-up aim arrow scales with the cast's range. This adapts per-rig automatically instead of assuming one fixed Euler fits every hand bind. - `artifacts/saber-academy/src/game/worldbvh.ts` — three-mesh-bvh helpers. `StaticWorldBVH.groundHeight(x, z)` raycasts the merged arena geometry and returns the floor Y or `null` (authoritative ground in both physics + fallback paths). `StaticWorldBVH.resolveWalls(x, y, z, radius, height)` pushes a character capsule out of penetrated wall geometry via a capsule-vs-triangle `shapecast` (`ExtendedTriangle.closestPointToSegment`), applying a horizontal-only correction so the flat floor is a no-op; `moveBody` layers it on top of the Rapier result so pillars stay un-clippable even when Rapier is unavailable. Used for precise weapon-vs-body melee with a segment-vs-capsule fallback.

## Architecture decisions

- The frontend fetches the hero roster from the api-server (`/api/saber/roster`), which reads Cloudflare D1 and returns each hero's public R2 GLB model URL + faction color. The game world itself (combat, physics, rendering) is still fully client-side three.js.
- Game logic is a plain TypeScript class driving three.js directly; React only renders the 2D overlays and reacts to an engine state subscription (`onUpdate`).
- Real skeletal animation everywhere. The Grudge Bip001 "kits" (no embedded animations, no clip-compatible packs) are driven by the Mixamo clip library **retargeted onto their Bip001 skeleton** at load time (see `retarget.ts`) via an `AnimationMixer` — not procedurally. The girl character **Lucy** is a real mixamorig-rigged FBX driven by the same library **directly** (same rig, no retargeting). Clip sets are chosen by **weapon category** (blade/magic/bow) so a sword-wielder and a mage animate differently. `updateCharacterAnim` runs the mixer path for any instance that has a `mixer` (covers both rigs); the old procedural model-group animation remains as the fallback when retargeting/clip load fails. Lucy is player-only (excluded from the enemy pool); her assets live in `public/models/lucy/`. A capsule humanoid is the final fallback. The **Heavy** ranged gunner enemy is also a real mixamorig FBX driven directly by its own clips (`public/models/heavy/`: `Heavy.fbx` mesh, `idle.fbx` aiming pose, `run.fbx`) — loaded best-effort in `start()` via `loadGunnerDef()`; when its assets fail it simply does not spawn.
- **Weapons are real, not procedural.** Each champion's embedded weapon mesh is a child of a hand container (`R_/L_hand_container`) in the GLB — *not* skinned — so it follows the hand through the bone hierarchy automatically. `pruneKit` just reveals the one mesh matching the roster `weapon` and hides the others; there is no per-frame attach for champions. Only Lucy/capsule (which have no embedded weapon) get a `makeBlade` katana placed via a per-instance grip. That grip is **skeleton-derived** (`gripFromHandBone`): the weapon's length axis is aligned to the hand bone's real finger direction read from the bone hierarchy, not a hardcoded Euler, so it adapts to each FBX rig's hand bind (Lucy, Racalvin, Heavy rifle) automatically — only a small per-weapon roll/seat is tuned on top.
- **Signature skills are derived client-side from existing roster data** (no api-server change): `classFor` maps a hero to one of five skill classes (classId → faction keyword → weapon category fallback), and `getSkills` returns its two skills. VFX textures load defensively from `https://assets.grudge-studio.com/effects/custom/<name>.png` — a tinted additive sprite shows immediately and the texture swaps in on success, so gameplay never blocks on the download.
- Bone-name matching is **colon-insensitive** (`norm = s => s.replace(/[^a-z0-9]/gi,"").toLowerCase()`): FBXLoader sanitizes `mixamorig:Hips` to `mixamorigHips`, so exact-colon lookups silently miss.
- Cloned GLB instances (`SkeletonUtils.clone`) share geometry/material with the cached template — never dispose the cloned body; only dispose per-instance resources (Lucy/capsule blade, health-bar texture, VFX sprite materials). The shared VFX texture cache is disposed once in `dispose()`, never per-sprite. See `disposeInstance` / `disposeEnemy` / `clearVfx`.
- **The third-person camera is self-owned, not the SDK's.** `grudge-studio`'s `ThirdPersonCameraController` was replaced by an in-engine orbit follow camera (`updateCamera`/`cameraShake` in `SaberGame.ts`): mouse `movementX/Y` (pointer-locked) feed `camYaw`/`camPitch` directly, the camera is placed behind+above the player along that yaw/pitch at `camDist`, raycast-pulled-in when an arena collider would occlude it, smoothly chased (frame-rate-independent lerp), and `lookAt`s the player's upper body. `camYaw` IS the camera heading (`atan2(fwd.x, fwd.z)`), so the existing camera-relative movement basis (`camForward`/`camRight`) and `camHeading` keep working unchanged. Only `grudge-studio`'s lighting is still used; keyboard input is handled manually (the SDK's keyboard path is incomplete). `three` must be deduped in vite (SDK bundles its own copy), and it resolves to **0.160.1** (pinned by the SDK) despite `package.json` claiming `^0.184` — verify the resolved version before assuming a loader/SkeletonUtils API exists.
- **Physics + collision are best-effort layers over the existing math engine, never a hard dependency.** Rapier (`physics.ts`) resolves only horizontal collide-and-slide; the engine still owns gravity, jump, and vertical velocity. three-mesh-bvh (`worldbvh.ts`) provides the authoritative ground height (used by both paths) and precise blade-segment-vs-body melee. Both init inside `ensurePhysics(token)` (startVersion-guarded), wrapped in try/catch — if Rapier WASM or BVH baking fails, `physics`/`worldBvh` stay `null` and movement falls back to math + flat ground (`?? 0`), melee falls back to segment-vs-capsule. A partially-built `PhysicsWorld` is disposed in the catch so a failed init does not leak. Lifecycle: enemy bodies+hitters are created only when physics exists (in `spawnEnemy`) and freed in `disposeEnemy`; the player body + world + static BVH are freed in `teardownPhysics` (called from `dispose` and at the top of `ensurePhysics`). Cloned-GLB geometry is shared, so only per-instance baked BVH geometry is disposed, never the body.

## Product

A third-person 3D action game. Choose a champion from the live roster, then fight as their real model wielding their real embedded weapon. A secret champion, **Racalvin the Pirate King**, can be summoned on the character-select screen by holding **R + SHIFT** (he then appears in the roster grid and is auto-selected). Pick a mode: **Survival** (five escalating waves) or **Testing Grounds** (a free-play sandbox to spawn/clear dummies and refill, with no waves or death). Enemy positioning is driven by a **Movement Motivation** system: each foe's weapon gives it a preference from "close the gap" (melee) to "keep distance" (ranged), which sets the range it tries to hold. From wave 2 onward, some foes are ranged **Heavy gunners** that kite (back off when you close in, advance when you stray, strafe to hold range) and fire tracer bullets — **block them**: a held block negates a bullet's damage just like a melee hit. Ranger and mage enemies fire real projectiles — visible arrows and glowing magic orbs — released at the loose point of their bow-shot/spell-cast animation (300ms in; staggering them inside that window interrupts the shot). Playing a **bow** champion makes LMB a ranged attack: the draw animation plays and an arrow flies at its loose point, aimed like casts (lock > soft focus > crosshair). Playing a **staff/mage** champion makes LMB an **Arcane Bolt**: a 1.5s cast (shown on the HUD cast bar, cast animation stretched to match) that then fires a pulsing magic orb dealing splash damage. Player and enemy projectiles use swept-segment collision and are fully purged on round clear/reset. Move with WASD (Shift sprint, double-tap a direction for a dodge-roll with brief invulnerability — usable once mid-air as an air dash, Space jump), look with the mouse (pointer lock). Lock onto foes with a tab-target system: press **Tab** to cycle the nearest enemies, or tap **right-click** to focus/lock-on the one under your crosshair (tap RMB again to release). While locked, your guardian squares up to the target and your attacks auto-aim at it; a red marker hovers over the locked enemy and the crosshair turns red. Left-click to strike: repeated clicks chain a combo, Shift+left-click is a heavy attack, and a left-click in mid-air is a plunging air strike. For blade-wielders (Lucy, Racalvin) the strike hitbox tracks the real animated blade point. Hold Shift+right-click to block, taking no damage but getting shoved back and draining force; time the guard to the incoming blow and it becomes a parry that negates the hit and stuns the attacker. Cast two class-specific signature skills with Q and E (each costs force and has a cooldown shown on the HUD skill bar). The **blade dancer** (Lucy) casts **Whirlwind Dash** (Q — spin forward through foes, shredding all in her path) and **Boomerang Blade** (E — hurl the blade out and back, carving enemies on both legs). Track health, force energy, score, and combo via the HUD. Menu, character-select, loading, game-over, and victory screens with restart.

**Meshy Academy recruits.** Four AI-generated heroes (Aldric knight, Sylvara mage, Corvin rogue, Kaela ranger) always appear at the end of the character-select roster. They were produced by `artifacts/saber-academy/scripts/meshy-pipeline.mjs` (Meshy text-to-3d → refine → auto-rig; resumable via a gitignored `scripts/meshy-state.json` that contains signed URLs and must never be committed) and ship as rigged GLBs in `public/models/meshy/<slug>/`. Meshy's auto-rig is a Mixamo-style skeleton WITHOUT the `mixamorig:` prefix (`Hips`, `Spine01/02`, lowercase `neck`, ...), so `retarget.ts` was generalized: `detectRetargetRig()` picks `BIP001_BONE_MAP` or `MESHY_BONE_MAP` (+ matching basis landmarks) and the bake cache keys per model × category for Meshy (per-character bind poses; bounded at `CACHE_MAX` entries, oldest evicted). `rig: "meshy"` heroes are player-only (excluded from the enemy pool by the existing `!h.rig` filter) and instantiate via `instantiateMeshyAnimated` (retargeted clips, `makeBlade` katana on `RightHand` through the skeleton-derived grip) with `instantiateMeshyModel` as the procedural fallback (no `pruneKit` — Meshy models legitimately carry shields/bags as part of their look) and capsule as the last resort.

## Gotchas

- WebGL cannot render in the headless screenshot environment ("BindToCurrentSequence failed") — 3D output cannot be visually verified here; the user must confirm appearance. Build defensively (capsule fallback, auto-normalize model scale/orientation).
- GLB models are large (9-11MB each). Only the player race + up to 4 enemy races are loaded; clones share cached geometry.
- Model scale/facing are auto-normalized (target height 2.0, feet at y=0, recenter x/z). If a model looks rotated or wrong-sized, adjust `TARGET_HEIGHT` / add a yaw offset in `characters.ts`.
